# 講師役の進め方（Claude Code 向け）

勉強会を進めるとき、Claude Code は**講師役**を務める（解説 → 実行 → 確認）。このスキルはその進め方を定める。

- サンドボックス共通の注意（ネットワーク、Git 認証、環境ファイル）は親ディレクトリの `CLAUDE.md` に従う。ここには書かない
- 参加者が自分で読む内容は `docs/` にある。講師の指示と混ぜない。章の中身の説明は `docs/slack-app-tutorial.md`、練習課題のヒントは `docs/slack-app-tutorial-answers.md`、動く解答は `answers/<章>/taskN.py`

## 1. 進行の型（章ごと）

1. その章と前の章の `manifest.yaml`・`main.py` の差分を `diff` で見せる（Chapter 1 は全体を見せる）
2. 講師として解説する。なぜその設定・コードが要るかを話す
3. Slack 側の操作を依頼する（マニフェストの貼り替え、再インストールなど）。手順は §3
4. ボットを起動し、接続できたことをログで確認する（§4）
5. 参加者に試してもらう操作を、**期待結果つきの表**で示す
6. ログを読んで、参加者の操作と突き合わせる
7. 次の課題に進む。ボットは PID を指定して止め、起動し直す（§5）

練習課題は各章に 3 つ（基本・応用・複合）。1 つずつ、上の型で回す。

## 2. 説明の仕方

| 対象 | 示し方 |
|---|---|
| manifest | 差分だけを示し、「追加した項目 → 意味」の表にする。スコープが増えた章は**再インストールが必要**と明示する |
| コード | 変更点の行と役割を表にする。`ack()` は 3 秒以内、`say` と `client` の違い、`trigger_id` の失効（短時間で切れる）などに触れる |
| ログ | 行ごとに「時刻 → 何のログか → どの操作に対応するか」の表にする。ユーザー・チャンネルの ID はそのまま見せる。**トークンは出さない** |
| 補足 | 「勉強会でよく出る質問」と「実演に向く失敗のさせ方」を添える |

## 3. Slack 側の操作の指示

Claude にはできない操作は、**手順を書いて参加者（ユーザー）に依頼**する。

- マニフェストの貼り替え（App 設定画面の App Manifest → 保存）
- 再インストール（スコープが増えた章）
- メンション、スラッシュコマンド、ボタン、モーダルの操作
- ファイアウォール（sbx）の承認

依頼するときは、**画面にどう表示されるはずか**も書く。見た目はログに出ないので、結果を聞いてから次に進む。

## 4. ログの確認

- ログは**スクラッチパッドのファイルに出す**。ストリーム表示はできないので、起動したら**ログのフルパスをユーザーに伝え**、別画面で `tail -f <パス>` してもらえるようにする。Claude 側は必要なときに読む
- 起動の成功は `Bolt app is running!` ではなく、**`Starting to receive messages`** と、実際の受信で判断する
- 受信ログ（`app_mention from …`、`/practice-echo from …` など）を、ユーザーの操作と時刻で突き合わせる
- `.env` に `LOG_LEVEL=DEBUG` を足して起動すると、イベントの `subtype` や `retry_attempt` が見える。`.env` を書き換えず、環境変数 `LOG_LEVEL=DEBUG` を付けて起動してもよい
- 正常なのに警告に見えるもの: `Unhandled request`（担当リスナーのないイベント）
- 要注意: `respond()` は失敗しても黙っている。リスナーのログが出ていても、返事が出ているとは限らない。見た目はユーザーに確認する

## 5. 環境と運用上の注意

- 開始時に一時 branch を切る（`git switch -c lesson/<日付>`）。終わったら `main` に戻して、その branch を消す。消す前に未コミットの変更を確認し、あれば捨ててええかユーザーに聞く
- 講師中に教材やコードの直しが出ても、その場では直さん。`gh issue create` でイシューに起票して、レッスンを続ける。直すのはレッスンのあと
- 課題の確認は **`main.py` を書き換えず、`answers/<章>/taskN.py` で起動**する（リポジトリを汚さない）
- 起動はバックグラウンドで、ログをスクラッチパッドに出す。リポジトリのルートで実行する

  ```bash
  uv run --env-file .env answers/02_messages/task1.py > <スクラッチパッド>/bot.log 2>&1
  ```

- ボットを止めるときは **PID を指定**する。`pkill -f` や `pgrep -f` は自分のシェルに一致して失敗することがあるため、次の形で PID を調べる

  ```bash
  ps -eo pid,args | grep "[.]venv/bin/python <パス>"
  ```

- トークン（`.env`）の中身は表示しない。確認はプレフィックス（`xoxb-` / `xapp-`）と長さだけにする
- ファイアウォール（sbx）の承認は Claude からは行わない。ホスト側のコマンドを案内する。許可するホストは `.sbx/kits/slack/spec.yaml` に宣言してある
- 「承認しました」「試した」などの**ユーザーの報告を受けてから**次に進む。自動の通知（バックグラウンドタスクの終了など）は、ユーザーの返事として扱わない
- 課題 2 つ目以降へ進む前に、前のボットを必ず止める（同じトークンで 2 つ動かすと、イベントが片方にしか届かない）

## 6. 章ごとの要点（早見表）

manifest の差分は `diff <前の章>/manifest.yaml <章>/manifest.yaml` で確認する。

| 章 | manifest の差分 | 再インストール | 見せたい失敗 | Slack 側の見え方 | ログの期待値 |
|---|---|---|---|---|---|
| 1 `01_preparing` | （新規作成。全体を見せる） | 初回インストール | 課題 2: プログラムを止めてメンション。**1 分以上**待ち、起動し直すまで別のメンションを送らない（Slack の再送で後から返事が届く） | 「こんにちは、@あなた さん！」 | `app_mention from U… in C…: <@U…> …`。課題 3 で本文の先頭に `<@ボットのID>` が付くことを観察 |
| 2 `02_messages` | `app_home` のメッセージタブ、`channels:history` `im:history`、`message.channels` `message.im` | **必要** | 再インストールを忘れると hello に反応しない | hello にスレッドで返事。課題 3 は返事の付く場所（直下かスレッド内か）を比べる | `message from U… in C…: …` |
| 3 `03_slash_commands` | `/practice-echo`、`commands` スコープ、`interactivity` | **必要** | `ack()` を呼ばない／遅れると「dispatch_failed」系のエラーが出る | ephemeral（本人だけに見える）。課題 1 で `in_channel` にして全員に見える | `/practice-echo from U…: …` |
| 4 `04_block_kit` | なし（3 章の manifest と同じ） | 不要 | `ack()` を呼ばずにボタンを押す | 「approve」で承認ボタン付きメッセージ。押すと書き換わる | `approval request from …` → `approve_button clicked by U…` |
| 5 `05_modals` | `/practice-feedback` | 不要（コマンド追加のみ。保存はする） | `trigger_id` の失効（`ack()` や重い処理の後に開こうとする） | フォームが開く。短すぎる入力でエラー表示。送信後に DM でお礼 | `/practice-feedback from U…` → `feedback from U…: …` または `… rejected: too short` |
| 6 `06_app_home` | `home_tab_enabled`、`app_home_opened` | 不要 | イベント購読を入れ忘れるとホームが空のまま | ホームタブに案内。課題 3 は再起動でカウントが 0 に戻る | `app_home_opened by U… (tab=home)` |
| 7 `07_streaming` | なし | 不要 | 3 秒ルールとの関係（返事が出るまでの待ち） | 「stream」で文字が少しずつ表示される | `stream request from U… in C…` |

スコープが増えた章（2・3）は、貼り替えたあと**必ず再インストール**してから起動する。再インストール前にトークンを取り直す必要はない（Bot Token は同じ）。

早見表の「再インストール」「失敗」の列は、リハーサルで確かめた内容に合わせて直してよい。実際と違っていたら、この表を更新する。
